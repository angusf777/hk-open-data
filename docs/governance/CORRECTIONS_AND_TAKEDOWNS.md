# Corrections and Takedowns

HK Open Data welcomes evidence-backed correction and takedown requests concerning accuracy, attribution, rights, security, privacy or provider representation.

## Request channels

Use the repository correction issue form for non-sensitive requests. For security issues or sensitive details, privately report through a GitHub Security Advisory and identify the request as a catalogue correction or takedown.

## What to include

- The catalogue resource ID and public page.
- The field, statement or artifact in question.
- An authoritative source URL supporting the request.
- The observed discrepancy or concern.
- The requested correction, removal or attribution.
- A safe contact method if follow-up is necessary.

Do not submit credentials, personal data, confidential correspondence or restricted provider payloads in a public issue.

## Process

1. **Acknowledgement:** the maintainer records receipt as capacity permits; no fixed response time is promised.
2. **Assessment:** the request is compared with the current repository, authoritative source and project policies.
3. **Interim protection:** a resource may be visibly flagged or removed from generated publication when continued display presents a credible immediate concern.
4. **Correction or takedown:** accepted changes are made through a reviewable commit and regenerated catalogue.
5. **Release record:** material corrections are described in the changelog or release evidence without exposing sensitive details.

Removal from this catalogue does not remove material controlled by an upstream provider. Disputed legal questions may require professional advice.
