# Security Policy

## Supported versions

Security fixes are applied to the latest released version and the `main` branch. Older releases may be unsupported; consult the release notes before deploying.

## Privately report a vulnerability

Please use the repository's private **GitHub Security Advisory** reporting form. Do not open a public issue for a suspected vulnerability, exposed credential, unsafe connector target, authentication bypass or sensitive-data disclosure.

Include the affected version or commit, component, reproducible steps, impact, and any safe proof of concept. Remove credentials, personal data and provider response bodies before submitting.

## Response expectations

The maintainer will acknowledge and assess reports as capacity permits. This solo-maintainer project does not promise a fixed response or remediation time. Confirmed issues may result in a private fix, coordinated advisory, release, connector disablement or documentation update.

## Safe-harbour intent

Good-faith research that avoids privacy violations, service disruption, data destruction and unauthorized access will be handled constructively. This statement does not authorize testing against upstream providers; their policies and applicable law remain controlling.
